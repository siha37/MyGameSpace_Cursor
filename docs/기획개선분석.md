# 현 기획 부족한 점 · 조작 불편 분석

> 대상: `docs/기획문서.md` v0.3 + 현재 MVP 구현  
> 목적: 코어 루프를 해치지 않으면서 **조작 마찰·기획 공백·검증 리스크**를 우선순위로 정리  
> 작성: 2026-09-14

---

## 요약

기획은 **“짧은 판단 → 즉각 처형”** 톤이 명확하지만, 실제 입력 체계는 **학습 비용이 높고 실패 피드백이 약하다**.  
특히 **달리기 2연타**, **상태별 악셀 방향 매트릭스**, **게이지=달리기 전용 충전**이 서로 묶여 조작 불편을 증폭시킨다.  
본편으로 가기 전에 **입력 단순화 / 실패 피드백 / 튜토리얼·리셋 규칙**을 먼저 다듬는 편이 안전하다.

## 1. 조작 불편 (우선 개선)

### 1.1 달리기 2연타 — 가장 큰 마찰

| 문제 | 상세 |
|------|------|
| 윈도우 0.25s가 빡빡함 | 의도적 질주와 미세 위치 조정이 충돌. 실수로 달리기가 켜지거나, 반대로 못 켠다. |
| 자원과 결합 | 게이지가 **달리기만**으로 차므로, 2연타가 “선택 기술”이 아니라 **필수 루틴**이 된다. |
| 방향 전환 비용 | 반대 방향 질주는 다시 2연타. 관성 감속과 겹치면 “급선회 = 입력 지옥 + 물리 지연”이 된다. |
| 공중 신규 질주 불가 | 착지 후 다시 2연타해야 충전이 이어져, 구간 이동 리듬이 끊긴다. |

**개선 제안 (택1 이상)**

1. **홀드 질주**: `Shift`는 악셀, 달리기는 `Ctrl` 또는 별도 키 홀드. (가장 직관적)
2. **탭 윈도우 완화**: 0.25s → 0.35~0.4s + 시각/청각 피드백.
3. **자동 질주 유지**: 한번 켜면 키를 떼도 보행 입력이 있으면 유지, 반대키/정지 시에만 해제.
4. **게이지 충전 경로 분리**: 달리기가 아니어도 약한 자연 회복(예: 0.15/s)을 두어 2연타 강제를 줄인다.

> 권장: MVP 직후 A/B — **(홀드 질주)** vs **(2연타 유지 + 약한 자연 회복)**.

### 1.2 WASD 이중 역할 + Shift 악셀

동일 키군이 **이동 / 질주 / 8방향 악셀 / 역분사**를 모두 담당한다.

| 상황 | 불편 |
|------|------|
| 질주 중 악셀 | `A/D` 홀드 + `Shift` → 의도치 않은 좌/우 악셀 |
| 대각 악셀 | `W/A/S/D` 조합 정확도가 요구됨. 프레임 단위 전투에서 오입력 비용이 큼 |
| 지상에서 `W/S` | 보행에는 안 쓰이지만 악셀에는 필요 → 초보에게 “죽은 키”로 보임 |
| 역분사 | 0.12s 대쉬 동안 **정확히 반대 1축** + Shift. 창이 너무 짧음 |

**개선 제안**

- 악셀을 **마우스 조준 방향 + 단일 키**(예: 우클릭 / `F`)로 분리하거나,  
  WASD 악셀을 유지하되 **조준 인디케이터**(허용 방향 하이라이트)를 상시 표시.
- 역분사: “정확 반대” → **대쉬 진행 방향과 120° 이상 벌어진 입력**으로 완화, 또는 **동일 키 재탭(Shift 더블)** 옵션.
- 금지 방향 입력 시 **게이지 미소모 + 짧은 거절 이펙트/사운드**. (현재는 무반응 → “고장난 입력”처럼 느껴짐)

### 1.3 마우스 커서 공격 vs 키보드 이동

레퍼런스(카타나 제로)는 **캐릭터 전방 고정 슬래시**에 가깝다.  
현 기획은 **커서 방향 공격 + 커서에 따른 전방 전환**이라 시선이 분산된다.

| 문제 | 영향 |
|------|------|
| 한 손 키보드 / 한 손 마우스 분리 | 악셀 연타 구간에서 커서 조준이 흔들림 |
| 전방 = 커서 | 이동 방향과 공격 방향이 어긋나기 쉬움 |
| 부착·악셀 중 공격 무시 | “붙어서 베기”가 불가능 → 벽 옆 처형이 **이탈 → 조준 → 클릭** 3스텝 |

**개선 제안**

- MVP 검증용으로 **전방 고정 공격**(이동/마지막 바라본 방향) 옵션을 두고 커서 조준과 비교.
- 또는 커서 조준을 유지하되 **부착 중 공격 1회 허용**(게이지/후딜 페널티)으로 벽 킬 템포 회복.
- 공격 가능/불가 상태를 **커서 색 / 크로스헤어**로 즉시 피드백.

---

### 1.4 상태별 악셀 방향 매트릭스 — 인지 부하

지상 / 공중 / 천장 / 좌벽 / 우벽마다 허용 방향이 다르다. 규칙은 논리적이지만 **암기 부담이 전투 템포와 충돌**한다.

특히 거슬리는 지점:

- **천장 부착 시 직선 하(`S`) 불가** — 낙하 이탈은 점프뿐. “아래로 박차기” 직관과 어긋남.
- **지상 하방향 금지**는 타당하나, 금지 시 무반응이면 학습이 느림.
- 벽 부착 중 “벽 쪽 방향” 금지도 동일.

**개선 제안**

- HUD 또는 캐릭터 발밑에 **8방향 허용 링** (불가 방향 dim).
- 천장: **하 방향 악셀 허용**(직선 하강 대쉬). 부착 이탈 UX가 단순해짐.
- 튜토리얼 룸을 “평지 → 벽 → 천장” 순으로 **한 규칙씩** 강제 연습.

---

### 1.5 부착 1초 + 공격 불가 = 강제 다운타임

부착은 스타일리시 앵커지만, 현재 규칙은:

- 1초 고정
- 방향키 이탈 불가
- 공격 불가
- 이탈은 악셀(자원) 또는 점프만

적 AI가 붙는 본편에서는 **벽에 붙는 순간이 약점**이 될 수 있다. MVP에서는 허수아비가 공격하지 않아 문제가 가려진다.

**개선 제안**

- 부착 시간 0.6~0.8s로 단축, 또는 **입력 있으면 즉시 이탈**(점프 없이도 아래 키로 드롭).
- 부착 중 **짧은 공격 윈도우** 또는 **자동 드롭 전 경고(0.2s 깜빡임)**.

---

### 1.6 입력 피드백 · 접근성 공백

기획 10장에 “키 리바인드 / 튜토리얼”이 미정이라, 아래가 전부 빠져 있다.

- 게이지 부족 / 쿨 0.1s / 금지 방향 / 공격 무시 상태 → **실패 사유 표시 없음**
- 게임패드·리바인드 없음 (Windows KB+M 고정)
- 달리·악셀·부착 상태의 **애니메이션/잔상/사운드**가 기획상 본편 이관 → MVP에서 “먹혔는지” 판별 어려움

**개선 제안 (MVP에 최소 반영)**

- 실패 시 플로팅 텍스트 또는 게이지 깜빡임 3종: `EMPTY` / `BLOCKED` / `COOLDOWN`
- 질주·악셀·부착 각각 1개씩의 임시 VFX
- 옵션: 키 리바인드 최소 세트 (이동/악셀/점프/공격)

## 2. 기획 문서 자체의 부족한 점

### 2.1 아직 비어 있어 본편 착수를 막는 항목

| 영역 | 현황 | 리스크 |
|------|------|--------|
| 타이틀·세계관·톤 | 미정 | 비주얼/사운드/카피 방향이 흔들림 |
| 스테이지·체크포인트·전투 사망 | `[TBD]` | 1피격 즉사 장르에서 **실패 루프**가 없으면 테스트·밸런스가 불가능 |
| 적 AI 수치 | 시야·사거리·턴 정지 전부 TBD | 방패병·기본 적 설계가 문서만 있고 검증 불가 |
| 방패 막힘 처리 | 정지 vs 넉백 미확정 | 악셀 코어 충돌 규칙이 불안정 |
| 악셀 충돌 우선순위 | 지형/방패/특수유닛 미정의 | 구현 시 예외 폭발 |
| HUD·히트스톱·이펙트 | 미정 | “스타일리시” 체감의 절반이 비어 있음 |
| 난이도·튜토리얼 | 미정 | 조작 복잡도 대비 온보딩 없음 |

### 2.2 내부 일관성 / 모호한 규칙

1. **천장 부착 허용 표**: 본문 4.5.3은 좌·우·좌하·우하, 하(직선)는 표에서 X. “아래에서 떼기” 의도가 점프 전용인지 명시 필요.
2. **악셀 중 상태 복귀**: 역분사 후 구현은 `Idle`로 두지만, 공중이면 `Jump`가 맞는지 문서에 상태 전이표가 없다.
3. **공격 중 이동 잠금**: 구현은 Attack 중 이동 처리 return. 기획 4.4는 후딜만 언급 — **후딜 중 이동 가능 여부** 확정 필요.
4. **질주 + 관성**: “달리기도 관성 턴”인데, 반대 질주는 2연타 재요구 → 의도된 무게감인지, 이중 페널티인지 문서화 필요.
5. **특수 유닛**: 즉사 예외만 있고 패턴 프레임워크(무적, 가드, 페이즈)가 없음.
6. **카메라**: MVP SmoothDamp만 있고, 악셀 시 look-ahead / 화면 흔들림 / 존 락 없음 → 본편 레벨 연출 공백.

### 2.3 코어 판타지 대비 콘텐츠 공백

플레이 루프는 `접근 → 처형 → 공압 회복 → 다음`인데,

- **유인**을 만드는 적 AI·시야가 MVP 밖
- **회복**이 달리기 노동에 묶임
- **스타일**을 보여줄 이펙트/히트스톱/사운드가 본편 이관

→ 지금 문서로는 “조작 프로토타입”은 가능해도 **한 판의 재미 검증**은 어렵다.  
허수아비 룸은 입력 검증용이지, 코어 루프 검증용이 아님을 문서에 명시하는 편이 좋다.

## 3. 디자인 리스크 (조작 외)

### 3.1 자원 루프가 전투를 왜곡할 수 있음

- 시작 2 / 최대 4 / 악셀 1 / 처치 +1 / 달리기 0.7/s
- 전투 중에는 처치로 순환 가능하지만, **탐색·실패 후·빈 구간**에서는 달리기가 강제됨
- “한 번의 실수 = 죽음”과 “달리며 게이지 파밍”이 톤상 어울리는지 재검토 필요

**개선**: 처치 중심 회복을 메인으로, 달리기는 보조. 또는 구간 진입 시 게이지 최저 보장(예: 입구에서 min 2.0).

### 3.2 1피격 즉사 + 복잡한 입력 = 가혹한 학습 곡선

입력 실수(금지 악셀, 역분사 실패, 2연타 미스)가 곧 사망으로 이어질 본편 구조다.  
튜토리얼·체크포인트·짧은 무적(리스폰 직후) 없이 난이도만 올리면 **불공정한 죽음**으로 읽힌다.

### 3.3 플랫폼·입력 장치

Windows KB+M만 명시. 액션 장르에서 패드 수요가 큰데 미지원이면 후반 공수 폭증.  
초기부터 **추상 입력 액션 맵**(이동, 질주, 악셀, 점프, 공격)으로 키를 감싸 두는 것이 좋다. (구현의 `InputHelper` 하드코딩 키와 기획 10장 “리바인드”가 아직 단절)

## 4. 개선 우선순위 제안

### P0 — 조작 마찰 완화 (플레이 가능 품질)

1. 달리기 입력 재설계 (홀드 질주 또는 윈도우/회복 완화)
2. 입력 실패 피드백 3종 (게이지/금지/쿨)
3. 천장 직선 하 악셀 허용 여부 확정
4. 공격 조준 방식 A/B (커서 vs 전방 고정)

### P1 — 본편 착수 전 필수 기획

1. 사망·체크포인트·리스폰 무적
2. 기본 적 1종의 수치 확정 (시야/사거리/선딜/턴 정지)
3. 악셀 충돌 우선순위 표
4. 튜토리얼 구간 플로우 (한 화면 = 한 규칙)

### P2 — 스타일·콘텐츠

1. 히트스톱·잔상·타격음 최소 세트
2. 방패병 막힘 결과 확정
3. 카메라 look-ahead / Cinemachine
4. 키 리바인드 · 패드

## 6. 결론

현 기획의 강점은 **규칙의 명확함과 즉사 액션의 판타지**다.  
약점은 **그 판타지를 전달하는 입력 경로가 과밀**하고, **실패가 조용히 무시**되며, **본편에 필요한 루프(적·사망·피드백)가 비어 있다**는 점이다.

조작 불편의 핵은 단일이 아니라 결합이다:

```
2연타 질주 필수 → 게이지 충전 → Shift+WASD 악셀 → 상태별 방향 제한 → 무반응 실패
```

이 사슬을 한두 군데만 끊어도(홀드 질주, 실패 피드백, 천장 하강 허용) 체감 난이도가 크게 내려간다.  
수치 튜닝보다 **입력 모델과 피드백**을 먼저 고치는 것을 권장한다.
